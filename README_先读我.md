## 同帧延迟和启动关联

测量起点 t0 是第一组有效 RAW 像素进入解包后的 FPGA 采集接口；终点 t1 是同一来源图像实际到达最终 HDMI 发射模块像素输入端。t1−t0 包括处理、DDR 等待和显示扫描等待，不含传感器曝光和显示器内部响应。整帧输出与读会话结算后才发布可信结果，因此页面显示最近已验证帧，有约一帧更新滞后。重复显示同一来源帧时保留原 t0，年龄继续增长。

V16 修正仅作用于延迟观察器：使用 camera 源 Gray 代号和实际 HDMI Gray 代号，经 2FF 同步、SOF 后再等待两个 DDR 时钟关联，避免 DDR 启动较晚、漏见本地事件时计数错绑来源。源时间戳不再仅靠本地见到的 SOF 次数猜测。观察器输出只去 HUD，不反向驱动像素、DDR 调度或系统复位。

如果原 RAW 来源队列因缺失打包 SOF 而已经歧义，仍保持无效，需共享复位恢复；不会借用最新 RAW 时间戳冒充同帧，也不承诺所有硬件启动物理原因均已被探测。K3 原因页和 V15 中文延迟/来源显示保留。V15 板上曾需等待或复位的现象是观测记录，不能直接据此认定唯一根因或保证本候选每次上电立即有效。
